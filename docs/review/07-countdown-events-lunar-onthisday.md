# 07 Countdown, Events, Lunar, OnThisDay

## P0
- None.

## P1
- `EveryTime/Features/Sleep/Nap/NapAlarm.swift:352`: the only `willPresent` delegate returns `[]` for every non-nap notification. A countdown that ends while the app is open on any other screen (Countdown list, World tab) makes no sound and shows no banner. The in-app celebration only runs on `CountdownDetailView`. Important-event and lunar 9:00 reminders are also swallowed if the app is open at 9:00. → Return `[.banner, .sound, .list]` for the `countdown.`, `important.` and `lunar.` prefixes. Keep `[]` only for a countdown whose detail screen is showing.
- `EveryTime/Features/Events/CalendarEventPicker.swift:41-51`: the search window starts 30 years back, and recurring events collapse to the earliest occurrence *inside that window*. Example: a Birthdays-calendar contact born 1980-03-10 is imported as 1997-03-10, so the app shows "Turns 30" in 2027 instead of 47. The yearly reminder title is wrong the same way. → For recurring hits, use the series start: take the master `store.calendarItem(withIdentifier:)` as an `EKEvent` and read its `startDate`. For birthday-calendar hits, ask the user to confirm the year in the editor, or read the contact's birthday through `birthdayContactIdentifier`.

## P2
- `EveryTime/Features/Countdown/CountdownNotifications.swift:27`, `Events/ImportantEventNotifications.swift:28`, `Lunar/LunarNotifications.swift:30`, `Sleep/JetLag/JetLagNotifications.swift:26`: the per-feature caps add up to 80 (jet lag 40, events 20, countdown 10, lunar 10), which is more than iOS's 64. Jet lag never checks for free slots. The four reschedulers run on separate queues and all start together on `.active`. Each one reads `pending` while the others are removing and re-adding, so `free` is computed from stale state. Example: 20 event reminders, 10 lunar and 3 countdowns are pending, then the user adds a trip. Jet lag adds 40, the total reaches 73 plus any activity alarms, and iOS silently drops the latest-firing ones (birthdays months away). Those reminders only come back after an app open that happens once enough jet lag notifications have fired. → Add one `NotificationBudget` with a single serial queue. It should gather the wanted requests from all features, reserve slots for the nap, wind-down and activity alarms, and give out the remaining 64 by fire date, with a small minimum per feature.
- `EveryTime/Features/Countdown/CountdownNotifications.swift:56`, `Events/ImportantEventNotifications.swift:61` (timed events): absolute instants are scheduled as floating `UNCalendarNotificationTrigger` components with no time zone. Example: a countdown for 20:00 New York time (00:00 UTC) is set, then the user flies to London without opening the app. The trigger fires at 20:00 London time, 5 hours early. The fall-back DST hour is ambiguous too. → Use `UNTimeIntervalNotificationTrigger(timeInterval: target - now)`, or set `when.timeZone = calendar.timeZone`. Keep floating components only for the all-day 9:00 reminders.
- `EveryTime/Features/Lunar/LunarCalendarView.swift:26`: deleting a lunar event leaves up to 24 exported events in the iPhone Calendar. `calendarEventIDs` is stored (line 66) but never read. Write-only access can't fetch the events to delete them. → When deleting an event that has `calendarEventIDs`, offer "Also remove from Calendar": request full access, then `store.event(withIdentifier:)` and `remove(_:span:)`. Otherwise say plainly that the Calendar copies stay.
- `EveryTime/Features/Events/CalendarEventPicker.swift:44-54`: `events(matching:)` over 32 years expands every recurring series. A daily standup alone produces about 11k `EKEvent`s, all held in memory before the loop keeps only the earliest of each. This makes the sheet slow and memory-heavy on busy calendars. → Fix it together with the P1 above: keep each `calendarItemIdentifier` once and resolve the master, or limit the expansion to the recent past and look the series start up separately.
- `EveryTime/Features/OnThisDay/OnThisDay.swift:141-149, 171-179`: `OnThisDayStore` is `@MainActor`, so its static `fetch`, `decodeFeed` (the `all` feed is about 1 MB of JSON), `readDisk` and `writeDisk` all run on the main thread. This causes a visible hitch each time the user steps a day with the chevrons. → Mark them `nonisolated` (or move them into a separate non-isolated type) so decoding and file IO run off the main actor.

## P3
- `EveryTime/Features/Countdown/CountdownDetailView.swift:126-135`: if the detail screen is open when the app goes to the background, the `Task.sleep` loop resumes on return and plays the sound, vibration and fireworks possibly hours late. The notification has already fired by then. → Celebrate only if `-remaining(at: .now) < 5s`; otherwise just show the finished state.
- `EveryTime/Features/Countdown/CountdownNotifications.swift:52-55`: a "time's up" notification is silenced by Focus. → Set `content.interruptionLevel = .timeSensitive`. The entitlement is already used by NapAlarm.
- `EveryTime/Features/Events/Anniversary.swift:91-92`: the switch on `d >= 730` doesn't guarantee `y >= 2` when the span crosses Feb 29. Mar 1 2027 → Feb 28 2029 is 730 days but `y == 1`, so the UI shows "1 years". → Switch on `y >= 2` (or `months >= 24`) and singularize the unit.
- `EveryTime/Features/Events/ImportantEventEditor.swift:44`, `Lunar/LunarCalendarView.swift:23`: if notification permission is denied, "Remind me" still shows as on and the bell icon still appears, but nothing is scheduled. → Check `notificationSettings()` and show "Notifications are off · Open Settings" under the toggle.
- `EveryTime/Features/OnThisDay/OnThisDay.swift:46`: always uses `en.wikipedia.org`. → Use `Locale.current.language.languageCode` when the feed supports it (de, fr, sv, pt, ru, zh, …), fall back to `en`, and include the language in the cache key.
- `EveryTime/Features/Lunar/LunarDate.swift:104`, `LunarCalendarView.swift:86,110`: every `body` pass builds a new `DateFormatter` and `Calendar(identifier: .chinese)`, and the converter re-runs this on every picker tick. → Cache the formatter and the calendar in statics.
- `EveryTime/Features/Lunar/LunarCalendarView.swift:86`, `OnThisDay/OnThisDayView.swift:5,13`: "Today" is read from `.now` once. If the app stays open past midnight, the lunar Today card and the OnThisDay default day stay on yesterday. → Wrap the Today card in `TimelineView(.everyMinute)`, or refresh on `.NSCalendarDayChanged`.
- `EveryTime/Features/Lunar/LunarCalendarView.swift:22-24`: the only way to turn a lunar reminder on or off after adding the event is a long-press context menu, which is hard to find. → Add a swipe action or an edit sheet.

## Improvements
- The three schedulers are copies of one another (queue, `isAuthorized`, stale removal, cap). Fold them into the shared budget scheduler above, where each feature supplies only `[UNNotificationRequest]`.
- Missing tests for pure logic: `ImportantEventNotifications.nextFire` (today before and after 9:00, Feb 29), `CountdownReadout` (boundary rounding), `CountdownEditor.Preset.date` (New Year), `OnThisDay.decodeFeed` (missing `pages`, BC years), and `Anniversary.elapsed` across Feb 29 (on Feb 28 2025 the Since card must agree with the "1st birthday" Today card).
- Checked with no issue found: the Feb 29 next anniversary (falls on Feb 28 in common years and returns to Feb 29 in 2028), the lunar year boundary and day-30 clamping (covered by tests), leap months (yearly events use the regular month and monthly events also fire in leap months, which is reasonable), identifier prefixes (no collisions), and cleanup of countdown and event notifications on edit or delete (every path calls reschedule).
