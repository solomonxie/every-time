# 02 Backup

Scope: `EveryTime/Backup/*` (incl. README), `Features/Settings/BackupListView.swift`, `BackupDocument.swift`. Demo isolation checked: every snapshot/apply path defaults to `UserDefaults.standard`, the demo suite is a separate domain and `demo.*` is outside `keyPrefixes`, so demo data never reaches a backup.

## P0
- none found.

## P1
- `EveryTime/Backup/BackupSnapshot.swift:39-41` + `:48-51`: `current()` keeps only `Data` values, but `apply()` removes every prefixed key missing from `entries`, including plain `@AppStorage` values that were never captured: `sleep.kind`, `sleep.nap.minutes`, `app.tab`, `sleep.health.asked`, `sleep.woke.dismissed`, `sleep.morning.dismissed`, `sleep.nap.alarm.system` (`NapAlarm.swift:123`). Result: (a) these settings never reach a new phone; (b) every restore/import wipes them; (c) restoring during an iOS 26 nap deletes the system-alarm ID, so `NapAlarm.cancel()` (`NapAlarm.swift:161`) can no longer cancel that alarm and "I'm up" leaves it ringing. Fix: back up plain property-list values too (encode `Bool/Int/Double/String` as JSON fragments, and on apply write back the native type), and exclude runtime state (`sleep.nap.alarm.system`, `sleep.nap.active`) via a deny-list. As a minimum, limit `apply()` removal to keys whose value is `Data`.
- `EveryTime/Backup/BackupArchiveName.swift:53-59`: the formatter has no `timeZone`, so names are stamped and parsed in the device's current zone. In a jet-lag app this is common: a backup at 08:00 Oct 16 in Tokyo (Oct 15 16:00 PDT) is named `20261016080000`, and a later one at 18:00 Oct 15 in SF is named `20261015180000`. `newestFirst` then puts the older file first, so `FirstRunRestore`/`latestBackup` restore stale data on reinstall, retention keeps the wrong "newest of day", and ages are off by up to ±26 h, so files can be pruned early. The DST fall-back hour has the same ambiguity. Fix: stamp new names in UTC (`timeZone = .gmt`, e.g. a trailing `Z` marker), keep parsing old names as local, and add a test that pins two zones.
- `EveryTime/Backup/FirstRunRestore.swift:12` with `AutoBackup.swift:16-17` and `BackupSnapshot.swift:57-66`: `isEmpty` treats any scalar (such as `world.localIndex` written on launch) as content, and the first-run `acceptable` check only asks whether the archive parses. Scenario: a fresh install's first-run download times out (30 s), so `doneKey` stays unset. The user turns on "Back up to iCloud Drive" and a settings-only archive is uploaded as the newest file. On the next launch `FirstRunRestore` applies that near-empty archive, sets `doneKey`, and never restores the real backup. Fix: `acceptable: { (try? BackupArchive.read($0))?.hasUserContent == true }`, and skip automatic uploads while `!hasUserContent && !didRestore`.

## P2
- `EveryTime/Backup/FirstRunRestore.swift:15-16`: this path skips what `BackupRestore.replace` does: no before-copy, no notification/widget reschedule. The `.active` reschedule already ran at launch, before the restore finished (it can wait up to 30 s), so restored countdowns, events and jet-lag reminders aren't scheduled until the next foreground. Also, `doneKey` is set only after a successful restore, so on a device that never found an archive the check reruns on every launch. If that user later empties all their lists, the newest iCloud archive (possibly from another device) silently overwrites the phone. Fix: route this through a shared `BackupRestore.afterApply()`, and set `doneKey` once the container is ready and either no archive exists or local content exists.
- `EveryTime/Backup/BackupRestore.swift:13-18`: the post-restore refresh misses `ActivityAlarms.sync` (restored planned-pin alarms aren't scheduled and stale ones stay pending until What Did is opened), `SleepCycle.current.apply()` (cached `SleepSuggestion` cycle length stays stale until relaunch), `Feeling.custom` (static cache), and `NapAlarm`/`WindDown` for the replaced `sleep.nap.active`/plan. Fix: add these to one `afterApply()` used by both restore paths.
- `EveryTime/Backup/AutoBackup.swift:39`: `beginBackgroundTask()` has no expiration handler. If `NSFileCoordinator` blocks while iCloud is busy (`CloudDrive.swift:95`), the task isn't ended in time and iOS kills the app. Fix: pass an expiration handler that cancels the Task and ends the task, and make `endBackgroundTask` idempotent.
- `EveryTime/Backup/BackupArchiveName.swift:44` with `LocalBackups.swift:34-36` and `CloudDrive.swift:82-89`: the export default name `YYYYMMDD-daily-every-time.zip` counts as "ours". If the user saves an export into Files → On My iPhone/iCloud Drive → Every Time (the obvious place), retention deletes it after 14 days unless it's the newest of its month. Fix: prune only `-auto-`/`-before-` names, or give exports a distinct kind (`-export-`) that is never pruned.
- `EveryTime/Backup/BackupSnapshot.swift:115-125`: `countedKeys` leaves out `timers.feelings`, `timers.feelingTags`, `timers.activityTags` and `boards.config`. Hundreds of feeling marks therefore show up as "1 setting" in the restore dialog summary, the row stats and the detail "now" comparison, so the user can't tell what a restore replaces. Fix: add these to `countedKeys`, with a test that every `[...]`-typed `@Stored` key under the prefixes is counted.
- `EveryTime/Backup/README.md:3-4,40`: "new keys travel automatically" and "`@AppStorage` views refresh themselves" are only true for `@Stored` (Data) keys. Fix: document the plain-value rule (or remove it with the P1 fix).

## P3
- `EveryTime/Backup/ZipArchive.swift:75-84`: `read` ignores the compression method, the data-descriptor flag and the CRC. An archive re-zipped by Files/Finder (deflate) reads as compressed bytes and gets "This isn't an Every Time backup". Fix: check `method == 0` and `flags & 8 == 0` and verify the CRC, so the error can say "unsupported zip". Also, writing DOS date 0 (`:23-24`, `:43-44`) is an invalid date (month 0); write 1980-01-01 (`0x0021`) or the real time.
- `EveryTime/Backup/AutoBackup.swift:47-49`: `enableAfterRestore` flips `isEnabled`, and `didSet` immediately re-uploads the archive that was just restored, as a duplicate "auto" file. Fix: record the restored fingerprint before enabling.
- `EveryTime/Backup/AutoBackup.swift:67-69` used at `BackupListView.swift:73,77`: `isUpToDate` builds a full snapshot and a SHA-256 hash on every body evaluation, twice per render. Fix: publish it after each backup and refresh it on foreground.
- `EveryTime/Features/Settings/BackupListView.swift:60`: the toggle is disabled whenever `status != .ready` (including `nil` while checking), so a user with iCloud off can't switch backup off. Fix: disable only turning it on: `.disabled(!backup.isEnabled && backup.status != .ready)`.
- `EveryTime/Backup/CloudDrive.swift:65-68`: one 30 s deadline is shared across all archives. A newest placeholder that never downloads uses it all, and older readable files then get a single poll each. Fix: give each file its own budget, or skip to the next file when its download hasn't started.
- `EveryTime/Features/Settings/BackupListView.swift:126-128`: every visible row downloads and parses its archive, up to about 30 iCloud downloads per list open. Fine at this size; consider caching stats by name and size.

## Improvements
- One `BackupRestore.apply(_:)` entry point (before-copy, apply, `afterApply`) for import, list restore and first-run restore.
- Store `createdAt` (UTC) as the source of truth for ordering and retention, and treat the file name as display only.
- Add tests for: plain `@AppStorage` keys surviving a restore, zone-change ordering, export files not being pruned, and settings-only archives being skipped by first-run restore.
