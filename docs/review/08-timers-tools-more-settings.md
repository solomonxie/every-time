## P1
- `EveryTime/Shared/TimerStore.swift:12-15` + `Features/Timers/ElapsedClock.swift:7-8`: all live timer state (stopwatch, Interview, Rehearsal, LeetCode clock + problem text) lives only in memory. Scenario: user starts the LeetCode timer and switches to Safari/LeetCode to solve. After 30-40 min iOS evicts the suspended app, and on return the clock reads 00:00, the problem name is blank and the session can't be saved. A force-quit or update does the same. → persist `startedAt`/`accumulated` (and laps, problem, difficulty) per clock under `timers.*` keys via `@Stored`/UserDefaults on every start/pause/reset. The wall-clock anchor already makes the restored value correct. Keep these keys out of backup.
- `EveryTime/Features/Timers/CountdownView.swift:136-157`: the time's-up signal is only `Task.sleep` + `.sensoryFeedback`. A suspended app runs neither. Scenario: 45-min Interview practice with the phone locked or another app in front. Nothing happens at zero, and the haptic only fires when the user reopens the app. Interview also "stops" late: `pause()` then records elapsed > duration. → on start/resume, schedule a `UNNotificationRequest` (time-sensitive, sound) for `duration - elapsed` with a fixed id per kind. Cancel it on pause/reset/minutes change. Optionally add a Live Activity with `Text(timerInterval:)`.
- `EveryTime/Features/Timers/WorkLog.swift:46-48`: `deleteDay` removes spans by their *start* day, but `days()` splits spans across midnight. Scenario: night shift, clock in 22:00 Mon, out 06:00 Tue. Swiping Tue (6:00) does nothing and the row comes back. Swiping Mon (2:00) also silently deletes Tue's 6 h. → trim instead of filter: for each span overlapping `[dayStart, nextDayStart)`, drop it if fully inside, otherwise clip its `start`/`end` to the day boundary (split a span that covers the whole day into two). Add a test.

## P2
- `EveryTime/Features/Timers/WorkTimerView.swift:43`: `CSVFile(text: log.csv())` is evaluated in `body`, which only re-runs when `spans` change (the 60 s `TimelineView` re-runs its content only, not the toolbar). Scenario: clock in at 09:00 and keep the screen open. Exporting at 17:00 without clocking out gives a CSV where today is missing (worked was 0 at render time, and `days()` drops days with `worked == 0`). → make `CSVFile` hold `spans` and build the text inside the `DataRepresentation` closure with `.now`, or move the `.toolbar` inside the `TimelineView` closure.
- `EveryTime/EveryTimeApp.swift:6,20-22` + `DemoSection.swift:10`: `TimerStore` is App-level `@State`, so live timers aren't isolated by demo mode, but `.id(demoOn)` recreates `TimerAlarms`, which reads minutes from the *other* store. Scenario: real Interview set to 30 min is running. Turning demo on re-arms the alarm with the demo's 45 min, so it doesn't stop at 30. Also, "Finish & Save" in demo writes a real session into demo history (and the reverse). → keep a separate `TimerStore` per mode (`demoOn ? demoTimers : timers`), or reset the shared store in `setDemo`.
- `EveryTime/Features/Timers/WorkLog.swift:42-58` / `WorkTimerView.swift`: spans can't be edited. A forgotten clock-out keeps running: every following day shows 24:00 worked, and the only fix is deleting whole days. → allow editing a span's start/end (or "clock out at…"), and when `openSince` is more than ~16 h ago, ask "Still working?" on appear.
- `EveryTime/Features/Tools/TimestampConverterView.swift:89-90`: only s vs ms is detected. Microsecond and nanosecond input (16/19 digits, e.g. Python `time_ns()`, Go `UnixNano`, Postgres) is read as ms → year ~57,000. Values like `1e300` give a nonsense date in every row. → detect by magnitude (`>1e17` ns, `>1e14` µs, `>1e11` ms), show the unit used, and reject values outside e.g. ±1e13 s with "Out of range". Optionally add a s/ms/µs/ns segmented override.
- `EveryTime/Features/Tools/TimestampConverterView.swift:5,39-40`: `date` starts as `Date()` with the current seconds and fraction, while the `DatePicker` shows only hours:minutes. Scenario: the user reads 14:30 in the picker and copies `…847`, not the `…800` they expect. → round `date` to the minute on init and in `onChange`, or use `.hourAndMinute` with seconds zeroed.
- `EveryTimeTests/`: no tests for `WorkLog.days/today/deleteDay/csv` (midnight split, DST day, open span), `ParsedTimestamp` (threshold, negative, ms boundary), `TimeText` (`countdown(0)`, negative) or `StopwatchModel.lap`. All are pure and cheap to test.

## P3
- `EveryTime/Features/More/MoreView.swift:109` + `ElapsedClock.swift:51`: `TimeText.countdown(max(0, remaining))` with `remaining == 0` returns `"+00:00"`, so the More row for a timed-out Interview shows `+00:00` while `CountdownView` shows `00:00`. → in the non-overtime branch use `TimeText.clock(Int(max(0, remaining).rounded(.up)))`.
- `EveryTime/Features/More/MoreView.swift:93`: the Work row runs a 1 s `.periodic` TimelineView whenever any span exists, even when clocked out for weeks. → `.animation(minimumInterval: 1, paused: log.state == .off)`, and hide the value when today has no work.
- `EveryTime/Features/Tools/CronExpression.swift:111`: an impossible but valid expression (`0 0 30 2 *`, `0 0 31 4,6 *`) scans 10,248 days on the main thread on every keystroke and every minute (`CronParserView.swift:9,38`). → pre-check DOM/month feasibility (no month has that day → return `[]`), or cache the runs by `text` + minute.
- `EveryTime/Features/Tools/CronExpression.swift:153`: `SAT-SUN` / `FRI-SUN` throw "goes backwards" because SUN = 0, although `5-7` works. → for `dayOfWeek`, map an upper name `SUN` to 7.
- `EveryTime/Features/Tools/CronExpression.swift:164`: `L`, `W`, `#`, `?` and 6/7-field Quartz/seconds syntax give "Invalid day of month "L"" / "Expected 5 fields, got 6". → a specific `CronError.unsupported` ("L/W/# are Quartz extensions, not supported"), and mention 5-field Unix cron in the hint line.
- `EveryTime/Features/Tools/CronExpression.swift:104`: runs are always in the device zone. Server crons usually run in UTC. → add a Local/UTC toggle (pass `calendar.timeZone = .gmt`). Note also that skipped DST times are dropped, while Vixie cron runs them right after the jump. State that in the UI or follow Vixie.
- `EveryTime/Features/Timers/BigClockView.swift:23` + `StopwatchView.swift:43`: the stopwatch's full-screen mode re-lays a 400 pt `Text` with `minimumScaleFactor(0.05)` at display rate (interval 0.01). The scale-to-fit search every frame keeps the CPU high in landscape. → cap the interval at 1/30 s, or size the font once from a `GeometryReader`.
- `EveryTime/Features/Timers/TimerControls.swift:15-24`: for LeetCode/countdowns (no `onLap`), the Reset button is live while running, right beside Pause. One mis-tap discards a long session with no confirm or undo. → confirm when `elapsed > 60`, or keep the last state for an undo toast.
- `EveryTime/Features/Timers/WorkLog.swift:101-102,111`: `h:mm` truncates while "Worked hours" rounds, so 7:59:59 exports as `7:59` and `8.00`. There's no zone column, so days logged while travelling are re-bucketed into the current zone on export. → derive both from whole minutes, and add a UTC offset column (or ISO 8601 start/end).
- `EveryTime/Features/Timers/WorkTimerView.swift:38`: haptic triggers on `spans.count`, so "Clock out" (closes a span, count unchanged) gives no feedback while the other buttons do. → trigger on `log.state`.
- `EveryTime/Features/Timers/ElapsedClock.swift:15`: a backwards wall-clock change while running clamps to `accumulated` (readout freezes), and a forward change jumps. That's acceptable for wall-clock anchors. If wanted, store `ProcessInfo.systemUptime` alongside and prefer it while the boot session is unchanged.
- `EveryTime/Features/Tools/UnixTimestampView.swift:6`: `.periodic(from: .now, by: 1)` isn't aligned to the second, so the big number flips up to ~1 s late. → `from: Date(timeIntervalSince1970: ceil(Date().timeIntervalSince1970))`.
- `EveryTime/Features/Settings/SettingsSections.swift:62,124-126`: the footer `message` is never cleared (a stale "Restored …" stays until relaunch). An archive encoding failure is reported as "Nothing to export yet." → clear on disappear or after a few seconds, and give `BackupArchive.make` failures their own message.
- `EveryTime/Features/Timers/LeetCodeView.swift:31-32`: swipe-delete of a history session has no undo. → undo toast, like the copy toast.
