## P1
- `EveryTime/Features/World/WorldView.swift:24-28,322-329`: the local row's id is `TimeZone.current.identifier`, the same as a saved city with that zone. Scenario: the user flies to London and the device zone becomes `Europe/London`, which is a default city. `rows` now has two rows with id `Europe/London`, so `ForEach(rows)` (TimelineGrid:73,129, cityPicks) gets duplicate IDs and rows render or animate wrong. A reorder then runs `cities = ids.filter { $0 != localID }`, which drops the saved London city without adding it to Recent. Back home, London is gone. → leave out of `rows` any city whose id equals `WorldCity.local.id` (keep it in `cities`), or give the local row its own id (`"local"`). In `move`, rebuild `cities` without dropping hidden entries.
- `EveryTime/Features/World/WorldView.swift:224-237`: the overlap finder checks 1-hour steps aligned to local `:00` and tests only `calendar.component(.hour)` in each zone. For half-hour and 45-minute zones the result is off by 30 or 45 min. Scenario: London (BST) + Kolkata (+5:30), both 08–18. The real overlap is 08:00–13:30 London. Local 13:00 is 17:30 in Kolkata (hour 17, counts), so the chip and the grid bar say 8 AM – 2 PM, and the last 30 min are 18:00–18:30 Kolkata. With Kathmandu (+5:45) it is 45 min over. When the other zone's start is the binding limit, the overlap is under-reported by the same amount. → step in 15-minute increments (every real offset is a multiple of 15 min) or intersect per-zone target intervals built with `calendar.date(bySettingHour:)` per day. Extract it into a pure, tested type (see Improvements).

## P2
- `EveryTime/Features/World/WorldView.swift:35,38,228` + `TimelineGrid.swift:8-12`: every scroll frame sets `cursor` (`onScroll`), which re-runs `WorldView.body`. That runs `overlapRanges(from: start, hours: 360)`, and for each of 360 × rows checks it reads `target` (a `@Stored` JSON decode, see step 01) and `row.calendar` (a fresh `Calendar` copy plus a time zone set). With 4 rows that is about 1,440 decodes and 1,440 calendar copies per frame at 120 Hz, plus `rows`/`overlapExcluded` decoded several times, so dragging the strip stutters. `HourCell` also gets a new `Calendar` per cell per pass. → compute the grid overlaps once in `@State`, recomputed `onChange(of: [cities, target, overlapExcluded, start])` and not per cursor change. Store a ready `Calendar` in `TimelineRow` (`let calendar`). Read `target` once into a local before the loop. Push `cursor` only into the views that need it (labels, hero, cursor line), e.g. a small `@Observable` cursor model, so the strips don't re-evaluate.
- `EveryTime/Features/World/WorldView.swift:5`: `start` is `@State` and set once. The World tab stays alive in the tab view, so after a few days of the app being suspended the window is lopsided. After 8 days "now" is past the end: `jumpToNow` clamps at the content end, the cursor line no longer matches the hero time, and the now marker is gone. The same happens if the device zone changes, because `start` stays the old zone's midnight. → recompute `start` on `scenePhase == .active` and on `.NSCalendarDayChanged` / `.NSSystemTimeZoneDidChange`, then `jumpToNow`.
- `EveryTime/Features/World/WorldView.swift:226,143-151,315-320`: if every remaining compared row is removed, `compared` is empty and `allSatisfy` is true for every hour. Scenario: exclude Local, NY and London, then remove Singapore. The overlap shows a full-day chip and green bars ignoring the target hours. With only the local row left (excluded), `cityPicks` is hidden (`rows.count > 1`), so it can't be undone. Removed ids also stay in `overlapExcluded`, so a city re-added from Recent comes back silently excluded, which contradicts "new ones count by default". → in `remove`, also delete the id from `overlapExcluded`. If `compared` is empty, fall back to all rows (or return `[]`).

## P3
- `EveryTime/Features/World/WorldView.swift:222`: the day overlap scans a fixed 24 h from local midnight. On a 25 h fall-back day the last hour is never checked. On a 23 h spring-forward day it adds 00:00–01:00 of the next day (an "All day" target shows 12 AM – 1 AM). → loop until `calendar.date(byAdding: .day, value: 1, to: first)`.
- `EveryTime/Features/World/TimelineGrid.swift:259`: the weekday/date marker shows only when a cell has `hour == 0`. Zones that spring forward at midnight (America/Santiago in September, America/Havana in March, Africa/Cairo in April) have no 00:xx hour that day, so the day's date marker is missing. → show the marker when `calendar.component(.day)` differs from the previous cell's day.
- `EveryTime/Features/World/TimelineGrid.swift:252-277`: in :30 and :45 zones the cells start at XX:30 or XX:45, but shading and the day marker are decided per cell by `hour`. The day/evening band boundary and the midnight marker are drawn 30 or 45 min late, and the 00:30 cell shows the date instead of "12:30". → acceptable as a design choice. If kept, draw the band edge and midnight tick at the exact offset within the cell (`minute / 60 * cellWidth`).
- `EveryTime/Features/World/WorldView.swift:57,64` + `WorldWallView.swift:8-9,17`: the wall gets copies of `cursor`/`followsNow` and never returns them. Closing a full-screen cover re-fires the presenter's `onAppear`, which calls `jumpToNow`, so a time picked on the wall (or before opening it) is lost. The same reset happens on every tab switch. The wall also gets no `overlaps`/`overlapRowIDs`, so its grid has no green bars. → pass `cursor`/`followsNow` as bindings. Only `jumpToNow` on first appear (or when `followsNow`). Pass the overlaps through.
- `EveryTime/Features/World/WorldView.swift:86-92,338-343`: `relativeLabel` ("in 2h") is computed from `cursor` vs now but only refreshes when `cursor` changes, so it goes stale while the user is idle. The 15 s tick also lets the "now" clock lag a minute change by up to 15 s. → wrap the hero in `TimelineView(.everyMinute)`, or sleep until the next minute boundary.
- `EveryTime/Features/World/WorldView.swift:197`: `hourText` uses `date(bySettingHour:of: .now)`. On a spring-forward day, hour 2 maps to 3:00, so the target wheels show "3 AM" twice (the same bug class as `UnfoldingRow` in step 01). → format from a fixed reference day.
- `EveryTime/Features/World/TimelineGrid.swift:248,269,291-294`: the hour labels are hand-built with hardcoded English "am"/"pm", and `uses12h` is cached in a static, so a locale or 24-hour setting change needs a relaunch. → use `Date.FormatStyle(timeZone:).hour(.defaultDigits(amPM: .narrow))`, or read the locale per render via `@Environment(\.locale)`.
- `EveryTime/Shared/CityPickerView.swift:39`: the title "Add City or Zone" also shows when JetLag `NewTripSheet.swift:123,127` uses the picker to choose an origin or destination. → add a `title` parameter.
- `EveryTime/Features/World/TimelineGrid.swift:79-99,111-119`: VoiceOver can't move the cursor (no adjustable action on the grid; it reads hour cells one by one), and rows can be reordered only by drag. → `.accessibilityAdjustableAction` on the cursor (±15 min), `.accessibilityActions` "Move up/down" on labels, and `.accessibilityHidden(true)` on the hour strips.

## Improvements
- Move the overlap logic (`overlapRanges`, `TargetHours`) into a pure `OverlapFinder` in `Models/` with tests: half-hour/45-min zones, wrapping target (22–6), "All day", 23 h/25 h days, an empty compared set. No tests cover World logic today.
- `TimelineRow` could carry a precomputed `Calendar` and `offsetLabel`, which removes repeated `TimeZone(identifier:)` lookups (`WorldCity.timeZone` builds a new one on every access) in `CursorLabel` and `HourCell`.
- `WorldView` (357 lines) repeats `date(atOffset:)`/`scroll(to:)`/the tick loop from `WorldWallView`. Move them into a shared `TimelineCursor` model that both views use, which also fixes the wall state hand-back.
