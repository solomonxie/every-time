## P1
- `EveryTime/Features/Boards/BoardStore.swift:177,216-221` + `CardSheet.swift:39,168`: writes rebuild the reminder from the *snapshot* `BoardCard`, not from the fresh `EKReminder`. `apply` sets title, due, priority and notes from the copy the sheet opened with, and `move` writes `card.notes` from the last load. Scenario: the user opens a card, edits its notes in Reminders on the Mac, then taps Save (or drags the card) on the phone. The Mac edit is silently overwritten. The design promises "user notes above are never touched". → In `edit`, re-parse `CardTrailer.parse(reminder.notes).body` from the fetched reminder and change only the trailer. In `save`, assign only the fields the user changed (diff against the original card), or refuse when `reminder.lastModifiedDate` is newer than the load time.
- `EveryTime/Features/Boards/BoardSettingsSheet.swift:173-175` + `BoardStore.swift:205-213`: renames run one after another, and each one refetches. Scenario: the user swaps the names "Doing" and "Review". The first pass moves Doing to Review, then the second moves *all* Review cards (old and new) to Doing, so every card ends up in one column. Chains (A→B, B→C) break the same way. → Fetch once and map `old → new` in a single pass, matching each card by its original column name: `renameColumns(in:_ map: [String: String])`.

## P2
- `EveryTime/Features/Boards/BoardStore.swift:208-212`: if `save(commit: false)` throws partway, the earlier saves stay pending in `store` and get committed by the next unrelated `save(commit: true)`, such as a drag, leaving a half-applied rename. → `catch { store.reset(); throw error }`.
- `EveryTime/Features/Boards/BoardStore.swift:179,221`: `isCompleted` is assigned on every save, even when it doesn't change. Setting `true` on an already completed reminder can restamp `completionDate` (EventKit's setter sets it to now). Scenario: fixing a typo on a Done card moves it into this week's velocity and burn-up. → Assign only when the value differs: `if reminder.isCompleted != done { reminder.isCompleted = done }`.
- `EveryTime/Features/Boards/BoardStore.swift:156-157` + `BoardMetrics.swift:121`: the flow snapshot's Done count is "completed in the last 90 days" (`doneWindow`), not cumulative. In the cumulative flow chart the Done band shrinks as old cards age out. A CFD band must never go down. → Record the cumulative done count (last snapshot's Done plus new completions), or drop Done from the CFD and plot only open columns.
- `EveryTime/Features/Boards/BoardMetrics.swift:91-94`: `velocityAverage` divides by all 8 weeks. That includes the current partial week and the weeks before the board existed (zeros), so the average reads low for new boards and early in the week. → Average only the completed weeks from the first week with any `createdAt`/`completedAt`.
- `EveryTime/Features/Boards/CardSheet.swift:67-68,185`: the due-date binding writes `[.year, .month, .day]` only. Scenario: the user changes the date of a reminder due 9:00 (set in Reminders). The time is dropped and the reminder's alarm time goes with it. → When `card.dueHasTime`, keep the hour and minute (or use a `.date + .hourAndMinute` picker in that case).
- `EveryTime/Features/Boards/BoardStore.swift:256`: `Milestone.id = eventIdentifier`, and every occurrence of a recurring event shares it. A repeating event in the milestone calendar gives duplicate IDs in `ForEach(map.milestones)` (`BoardRoadmapView.swift:30`), so rows go missing or are reused. The `UUID()` fallback also changes the ID on every fetch. → `id: "\(eventIdentifier ?? "")|\(startDate.timeIntervalSince1970)"`.
- `EveryTime/Features/Boards/BoardStore.swift:137-138,143`: the `fetchReminders` completion runs on an EventKit background queue but calls `Self.card`, which inherits `@MainActor` from the class. This is tolerated in Swift 5 mode, but it is a compile error or a runtime isolation trap under Swift 6/strict concurrency. → Mark `card(_:)` (and `CardTrailer` use) `nonisolated static`.
- `EveryTime/Features/Boards/BoardStore.swift:27,49,55-58`: (a) `requestFullAccessToReminders` needs `NSRemindersFullAccessUsageDescription`, which was removed from `Info.plist`. Re-enabling without it crashes on tap. The re-enable list in `IMPLEMENT_PLAN.md:20` mentions this, but `project.yml:27` doesn't. (b) `refresh()` updates `access` after a trip to Settings but never calls `store.reset()`. An `EKEventStore` created before authorization can keep returning no calendars, so every board shows "This Reminders list is gone" and invites "Remove board". → Add the plist key to the `project.yml` comment, and in `refresh()` call `store.reset()` when `access` changes. Note that `Lunar`/`Events` each create their own `EKEventStore`. Share one per app (step 12).

## P3
- `EveryTime/Features/Boards/BoardStore.swift:157`: `grouped` has a hidden side effect: it re-encodes the whole `boards.flow` history and writes it to UserDefaults on every load (and for every board in `BoardsListView.load`). Snapshots are also keyed by column *name*, so a rename erases that column's flow history. → Record in a separate `snapshot(board:)` call once per day, and key by `BoardColumn.id`.
- `EveryTime/Features/Boards/BoardView.swift:53,169,176-182`: each write loads three times (`reload()`, our own `EKEventStoreChanged`, and the sheet `onDismiss`) in unstructured Tasks that are never cancelled. → Rely on `revision` only and drop `reload()`.
- `EveryTime/Features/Boards/BoardView.swift:171-174`: `moves += 1` plays the success haptic even when the move threw. → Bump it only on success.
- `EveryTime/Features/Boards/BoardColumnsView.swift:33,122`: dragging a plain `String` means any text dropped from another app is accepted as a drop target (it is rejected later, but the lane still highlights and pages). The 600 ms paging Task (`:71-74`) is never cancelled. → Use a `Transferable` `CardDrag(id:)` with its own `UTType`, and keep a cancellable `Task` in state. The identity itself (`calendarItemIdentifier`) is fine within a session.
- `EveryTime/Features/Boards/BoardColumnsView.swift:56-63`: WIP limits are shown but not checked on drop or "Move to". → Warn (haptic plus a label) when the target lane is at its limit.
- `EveryTime/Features/Boards/BoardStore.swift:87,92`: in demo mode the configs come from the demo store, but EventKit is real, so demo edits change real reminders. → Hide Boards in demo mode, or make them read-only there.
- `EveryTime/Features/Boards/BoardModels.swift:68-74`: `dueDate`/`isOverdue` repeat `BoardMetrics.swift:33-38` with a hard-coded `Calendar.current`. → Keep one version (on `BoardMetrics`, or pass the calendar in).
