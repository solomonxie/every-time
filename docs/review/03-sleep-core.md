# 03 Sleep core

Scope: `EveryTime/Features/Sleep/*.swift` (top level), `EveryTime/Models/SleepSuggestion.swift`. Callees checked: `Nap/NapAlarm.swift` (`NapSession`, `NapAlarm`), `Nap/NapAdvice.swift`. Cycle math uses absolute intervals (`addingTimeInterval`), so DST and a zone change mid-night don't move the alarm or the cycle grid. `ActiveNap`, AlarmKit `.fixed` and `UNTimeIntervalNotificationTrigger` are all absolute. The DST problems are in ring drawing only.

## P0
- none found.

## P1
- `EveryTime/Features/Sleep/WakeCheck.swift:17,22-24` used at `NightScreen.swift:121-124`: `asleep` is clamped at 0, so during the first `latency` minutes `nextCycleEnd = now + cycle`, not `start + latency + cycle`. Scenario: fall-asleep set to 30 min. You tap Sleep at 23:00 and open the "Up at" chips at 23:02. They offer 00:32, 02:02, 03:32…, but the real grid is 01:00, 02:30, 04:00. A tap moves the alarm (`moveAlarm`) into deep sleep, up to `fallAsleepMinutes` (max 45) early. Fix: `nextCycleEnd = start + latency + Double(cycles + 1) * cycle` (or add `max(0, latency - elapsed)` to `toCycleEnd`). Add a test at `elapsed < latency`.
- `EveryTime/Features/Sleep/SleepRing.swift:96-99,199-202,131`: `start` is clamped to `>= 0`, and `cycles()` uses it as the origin. Once asleep (`plan.start < now`), the deep-sleep bands and cycle-end ticks are drawn from now plus another fall-asleep, not from bed. They drift as the night goes on. Scenario: asleep at 23:00 with the alarm at 06:15 (5 cycles). At 01:00 the ring shows cycle ends at 02:45, 04:15, 05:45, and the alarm marker sits inside a deep band. The progress arc `arc(start, max(start, offset(now)))` is `arc(0, ~0)`, so it never shows. Fix: for the cycle grid use the unclamped `offset(plan.start)` (the `$0 + cycle > 0` filter already handles negative origins), and pass `nap.fallAsleep`. Either drop the dead progress arc or draw it from the unclamped start.
- `EveryTime/Features/Sleep/WakeCheck.swift:79,83-88`: `learned` minimizes absolute error over 70...120, and `min` keeps the first tie, so harmonics pull the result to the shortest length. Scenario: a regular sleeper wakes naturally after 445/450/455/448/452 min asleep. Costs: 75 min = 14 (6 cycles), 90 min = 14 (5 cycles), so it learns **75**. From then on every chip, ring detent, score and "between cycles" verdict runs on a 75-min grid. Absolute error also favours short lengths, since the worst-case error is L/2. Fix: score the phase error `|m/L - round(m/L)|`, add a prior term toward 90 (such as `λ·|L−90|`), and break ties toward 90. Add the test above.
- `EveryTime/Features/Sleep/WakeCheck.swift:161-166` with `PastNights.swift:40-42`: `debt` takes the 7 newest *entries*, not 7 days, and charges a full `need` to each. (a) A logged 3 h+ daytime sleep (after a night flight or night shift) counts as its own "night", so sleeping 13:00–16:30 *adds* ~4 h of debt instead of paying it back. Only Health nights are deduplicated per day. (b) With few logs, nights from weeks ago still count, although the label says "over the last 7". The same double-day entries stack two bars past 100 in `ScoreChart` (`PastNights.swift:136-138`). Fix: group nights by wake day (sum asleep), limit to `end >= now - 7 days`, and treat extra same-day long sleeps as naps.
- `EveryTime/Features/Sleep/Nap/NapAlarm.swift:138-146` (callers `NightScreen.swift:88`, `SleepTimeView.swift:159`, `NightScreen.swift:277`; overlaps step 04): `schedule` runs `cancel()` and then awaits, and `systemKey` is written only after the await. If the user taps two "Up at" chips quickly, two `moveAlarm` Tasks overlap. The second `cancel()` sees no key, both AlarmKit alarms get scheduled, and only the last ID is stored. The first alarm then rings at the old time, and "I'm up"/Cancel can't remove it. The same happens with Cancel during an in-flight schedule, and in the app path the notification chain is added after the cancel. Fix: keep one `scheduleTask` and cancel/await it before starting a new one, or use a generation counter. After the await, if the generation changed, cancel the alarm ID that was just created and skip the chain.

## P2
- `EveryTime/Features/Sleep/SleepTimeView.swift:57` with `NapAlarm.swift:125`: `NapAlarm.kind` is `.system` only while a system alarm ID is stored, so on the idle page it is always `.app`. On iOS 26 with AlarmKit authorized and notifications denied, the page warns "Alarm can't ring — notifications are off", but the alarm would ring. The check also runs only once per `.task`, so after "Turn on" the warning stays until the view reappears. Fix: base it on `#available(iOS 26)` plus `AlarmManager.shared.authorizationState`, and re-check on `scenePhase == .active`.
- `EveryTime/Features/Sleep/SleepRing.swift:105-106,241-244,374-376`: offsets are elapsed minutes, but the face places hours as `hour*60 - minutesOfDay(top)`. On a DST night every mark after the change is off by 1 h. Scenario: fall-back night with the ring opened at 23:00. Dragging the alarm onto the "6" label sets 05:00 (the readout says 05:00), and a 07:00 alarm is drawn at the 8 o'clock position. Fix: place face labels at `offset(calendar.nextDate(matching: hour))` and compute `degrees` from the date's wall-clock minutes, not `offset + rotation`. Alternatively, accept this and note it in a comment.
- `EveryTime/Features/Sleep/PastNights.swift:68-70`: the choice between asleep and in-bed samples is global. If any asleep sample exists in the 15 days, nights recorded only as `inBed` (nights without the Watch, iPhone sleep schedule) are dropped. Fix: build sessions from asleep samples, then add in-bed-only sessions that no asleep interval overlaps.
- `EveryTime/Features/Sleep/SleepTimeView.swift:363`: `storedNaps` is read inside `ForEach`, and each read JSON-decodes every nap (`Stored.swift:15`). With "Show all" that is O(rows × naps) decoding on every minute tick. Fix: use the `naps` already decoded in `idle` and pass a `[UUID: Nap]` dictionary.
- `EveryTime/Features/Sleep/SleepTimeView.swift:363-370`: a night merged from several stretches (night 23:00–05:00 plus a re-sleep 05:20–07:00) keeps only the first stretch's `source`. Delete/Edit act on 23:00–05:00 only, and the 05:20–07:00 part reappears as a separate nap. Fix: keep `sources: [UUID]` on `PastNight`, delete all of them, and offer editing per stretch.
- `EveryTime/Features/Sleep/SleepTimeView.swift:231-234` vs `:69-74`: `log` (morning card, "+" sheet) doesn't write `ActivityLog`, but editing first removes and then records. A logged sleep is missing from What Did until someone edits it. Fix: record in `log` as well, through one shared helper.
- `EveryTime/Features/Sleep/SleepHero.swift:125-126` with `SleepTimeView.swift:19,127`: `kind` persists, and its default is `.nap`. The block only stops *tapping* Nap. At 23:00, a user who last napped gets Nap mode with a dimmed but selected tile and a "Nap now · up at 23:20" button. Fix: in `idle`, use `.sleep` as the effective kind while `napTip != nil`.
- `EveryTime/Features/Sleep/NightScreen.swift:36`: `NightDim` also applies to `.woke`, so the daytime "Good morning / How do you feel?" screen opens at 20% brightness. Fix: apply it only for `.waiting/.asleep/.ringing`.
- `EveryTime/Features/Sleep/SleepTimeView.swift:114-137`: the bed/wake resolution (picked, usual, resleep, snap, shortest) is the most intricate logic on the page, and it is untested and inline in a view builder. Fix: move it into a pure `SleepPlan.resolve(now:naps:health:profile:storedBed:storedWake:kind:napMinutes:)` with tests (inside usual hours, picked bed in the past, resleep, stale `storedWake`).

## P3
- `EveryTime/Features/Sleep/NightScreen.swift:154`: `woke` builds `WakeCheck` with the default latency even for `resleep` naps. Pass `latency: nap.resleep == true ? WakeCheck.fallBackAsleep : …`.
- `EveryTime/Features/Sleep/SleepTimeView.swift:486`: "after three such wakes" contradicts `SleepCycle.minWakes = 5`. Interpolate the constant.
- `EveryTime/Features/Sleep/SleepTimeView.swift:42`: a 1 Hz `TimelineView` runs for the whole night, though the countdown shows seconds only under 1 h. Use `.everyMinute` when the next event is more than 1 h away.
- `EveryTime/Features/Sleep/SleepRing.swift:161`: `sensoryFeedback(.selection, trigger: end)` fires every 10 min with no touch, because `top` advances and `end` is relative to it. Add a condition: `{ _, _ in dragging != nil }`.
- `EveryTime/Features/Sleep/SleepHero.swift:142-143`: each of the two tiles attaches the same `.alert(isPresented: $showsNapTip)` and the same `sensoryFeedback`, so the haptic fires twice. Move both to `kindTiles`.
- `EveryTime/Features/Sleep/SleepHero.swift:68`: the nap wake caption is hard-coded "Today", which is wrong for a nap that crosses midnight. Reuse the Today/Tomorrow logic from `readout`.
- `EveryTime/Features/Sleep/WakeCheck.swift:170-179`: `wakeStreak` counts "in a row" without checking that the nights are on consecutive days, so gaps don't break it.
- `EveryTime/Features/Sleep/SleepTimeView.swift:54-58`: `.task` reruns on every tab return: two HealthKit queries (14 and 30 days) and a relearn. Throttle to once per foreground or day.
- `EveryTime/Features/Sleep/SleepTimeView.swift:365-366,377-378`: rows use `onTapGesture`, which VoiceOver doesn't expose as a button. Use `Button` or `.accessibilityAddTraits(.isButton)`. `SleepRing.swift:163-165`: add `accessibilityAdjustableAction` to step the alarm by cycle.
- Dead code: `SleepSuggestion.nextOccurrence` (`Models/SleepSuggestion.swift:38`, used only in tests), `WindDown.pending()` (`WindDown.swift:25`), `SleepSuggestion.wakeTimes` (tests only).
- `EveryTime/Models/SleepSuggestion.swift:5-6`: the cycle settings are `nonisolated(unsafe)` mutable statics that most sleep math reads implicitly. Tests have to reset them (`useDefaultCycle()`), and parallel tests can race.

## Improvements
- Split `SleepTimeView` (546 lines): `SleepHistorySection`, `SleepInsightsSection`, `MorningLog` (its own file, already pure), a shared `Toast` modifier, and the `SleepPlan` resolver above. The view would then keep only routing (active/woke/idle) and sheets.
- Pass a `SleepCycle` value (cycle and latency) into `WakeCheck`, `WakeFit`, `SleepNow`, `SleepRing` instead of reading `SleepSuggestion` statics. This makes the P1 math testable without global state.
- Add tests for `SleepRing` geometry (`offset`/`degrees` round-trip, DST night), `NightScreen.upAt`, `MorningLog.proposal`/`usualHours`, and `PastNights.load` with mixed asleep and inBed samples.
