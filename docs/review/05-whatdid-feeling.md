# 05 What did and Feeling

Scope: `EveryTime/Features/WhatDid/` and `EveryTime/Features/Feeling/`, all files read in full. Callers checked: `Sleep/Nap/NapAlarm.swift` (`NapSession`), `Sleep/SleepTimeView.swift`, `Shared/Stored.swift`, `Backup/BackupSnapshot.swift` (all keys are under `timers.`, so they are backed up), and `EveryTimeTests/ActivityLogTests.swift`.

## P0
- None found.

## P1
- `WhatDid/ActivityLog.swift:165-175` + `WhatDid/WhatDidView.swift:84`: you can't delete or move a pin that a daily repeat created. `dueRepeats` checks again on every redraw whether a pin with the same tag sits within 2 min of each past occurrence. Scenario: daily "Work" at 09:00. On Saturday the user deletes the auto-added 09:00 Work pin, and within a minute `.task(id: now)` adds it back. If they move it to 09:30 instead, a second Work pin appears at 09:00. → Record which days have been handled on the source mark (e.g. `materializedThrough: Date`) and only add occurrences after that date.
- `WhatDid/ActivityLog.swift:147,168` + `:328-329`: daily pins silently stop after 14 days. Both loops run `1...repeatDays` counted from the pin's original `mark.time`. Once that pin is more than 14 days old, nothing more is planned or added. The repeating `UNCalendarNotificationTrigger` keeps firing every day, so the alarm rings for a pin the timeline no longer shows. The editor footer ("two weeks ahead") suggests a rolling window. → Start the loop at the first day after `max(mark.time, materializedThrough, now - 14d)`, computed with `calendar.dateComponents([.day], from:to:)`.
- `WhatDid/WhatDidView.swift:443-445`: `setTag` rebuilds the mark as `ActivityMark(id:time:tag:)` and drops `alarm` and `repeats`. Scenario: a daily "Gym 07:00" pin with an alarm. The user selects it (its row or its plan), taps a different tag, and the daily repeat and the alarm are both gone, with no warning. → `marks = marks.map { var m = $0; if m.id == id { m.tag = tag }; return m }`.
- `WhatDid/WhatDidView.swift:426-428`: the "reuse a pin at the same time" rule ignores moments. Scenario: Start Work at 09:02 (stored as 09:00). Tap Coffee at 09:04 and `near` is the Work pin, so it is retagged to Coffee. Coffee is a moment, so the Work stretch disappears and the earlier span now runs on. The reverse also happens: Coffee, then Work within 2 min, loses the coffee. → Only reuse `near` when `Activity.of(near.tag).isMoment == activity.isMoment`. Otherwise append.
- `WhatDid/ActivityLog.swift:322`: alarms are never updated after an edit. A request already pending under the same id is skipped. Scenario: plan Dentist 14:00 with an alarm, then change it to 15:30 in `MarkEditor`. The notification still fires at 14:00, and its title still shows the old tag. → For each wanted mark, compare the trigger and content of the pending request (or keep a hash of time+tag in `userInfo`), and remove and re-add when they differ.
- `WhatDid/ActivityLog.swift:131,231-233,246` + `WhatDidView.swift:241`: a "night" is `Nap.nightLength`, which is 15 min + 90 min = 1 h 45 m (and changes as the cycle is learned). The comments and the UI text say "3 h or longer". Scenario: a 2 h afternoon nap from 14:00 to 16:00 counts as a night. The typical Bed and Wake (circular mean of 23:30 and 14:00) jump by hours, and `nights` goes up. A re-sleep after the alarm (`NapSession.sleepMore`) also counts as a second night once it reaches 1 h 45 m. → Use a fixed threshold (e.g. `3 * 3600`) that matches the text, or update the text. Merge sleep spans that touch (end == next start) before filtering nights.
- `Feeling/FeelingLog.swift:96-104`: `starting` also closes stale open feelings at the new time. Scenario: Happy was started yesterday at 09:00, never ended, and stopped showing at 21:00 (`maxOpen`). Today at 10:00 the user taps Sad. Happy gets `end = today 10:00`, and since `spans` doesn't cap explicit ends, it now shows as a 25 h stretch on the ring, in the list and in DayRow. → Set `ended.end = min(time, mark.start + maxOpen)`. Or only end marks that `active(at: time)` returns.

## P2
- `Feeling/FeelingLog.swift:96-106`: starting a feeling at a past cursor time breaks "one of a kind at a time". Scenario: Happy is open since 10:00. At 14:00 the cursor goes to 08:00 and the user taps Sad. Sad gets 08:00 with an open end and overlaps Happy, and both show as active. → When starting at `time`, set its end to the start of the next same-kind mark after `time`, if there is one.
- `WhatDid/WhatDidView.swift:142,152,172`: for a daily occurrence, `selectedSpan` and `onHoldPin` look up `marks` by the occurrence's made-up id (`occurrenceID`), which no stored mark has. "Edit or remove this pin" and long-press on the ring do nothing. Tapping a tag while an occurrence is selected adds a second plan at the same time, because `near` only searches real marks. → Resolve with `span.source ?? span.id` everywhere (the context menu at `:367` already does this).
- `WhatDid/WhatDidView.swift:104-105,151-152,420-423`: the list protects Sleep pins ("From the Sleep page", `:404`), but the ring long-press dialog, the "Edit or remove this pin" button and a retag by selection all still edit or delete them. Afterwards `SleepTimeView` (`ActivityLog.remove(.sleep, at:)`) can't find the pin, and the two pages disagree. → Use one `isManaged(span)` guard in all four places.
- `WhatDid/WhatDidView.swift:109,117` + `ActivityLog.swift:52,291-301`: `taken` doesn't include `sleep`, `nap` or `wake`. A custom tag named `nap` is rewritten to sleep on every `onAppear`, and pins tagged `wake` are deleted. A tag named `sleep` turns into the built-in Sleep. → Add `["sleep"] + ActivityLog.oldTags` to `taken`, and run the migration once behind a flag.
- `WhatDid/ActivityRing.swift:331-334,346-348`: `fraction` divides by a fixed 86 400 s. On DST days (23 h or 25 h) every arc and the cursor after 02:00 sit 1 h off the hour labels, which come from `bySettingHour`. A tap at the "18" label pins 19:00 on the spring-forward day and 17:00 in autumn, and the last hour of the autumn day wraps past midnight. Happens twice a year. → Use `fraction = (h*3600+m*60+s)/86400` from `dateComponents`, and in `time(at:)` build the date with `calendar.date(bySettingHour:minute:of: window.start)`.
- `WhatDid/ActivityLog.swift:227,248`: `dayCount = ceil(window.duration / 86400)`. The 7 calendar days spanning the autumn DST change last 169 h, so this gives 8. For that week every per-day average and meals-per-day value is 12.5 % low. In the first week of use, a window of 1 d 1 h divides by 2. → `max(1, (window.duration / 86400).rounded())`, or count calendar days.
- `WhatDid/ActivityLog.swift:193-198`: the 12 h cap applies only to the last pin. Once a later pin exists, the earlier stretch grows back to its full length. Scenario: Fun at 20:00, nothing tapped until Eat the next day at 20:00. Fun shows 12 h until the Eat tap, then 24 h in DayRow and in the 7-day averages. → Cap every span at `start + maxOpen` and leave the gap blank, or show over-long spans as "Untagged".
- `WhatDid/ActivityLog.swift:145,158`: `planned` includes moments as split points, while `spans` excludes them. A planned Coffee at 10:00 cuts a planned Work 09:00–12:00 down to 09:00–10:00. → Choose `next` from non-moment plans only, as `spans` does.
- `WhatDid/ActivityRing.swift:58,283-295`: the `DragGesture(minimumDistance: 6)` attached with `.gesture` on a 300 pt Canvas inside the `ScrollView` takes every drag that starts on the ring. Off-track drags hit the guard and do nothing, but they still don't scroll the page. → Recognize the drag only when it starts on the track (e.g. iOS 18 `UIGestureRecognizerRepresentable` with `shouldBegin`), or require a short long-press before the drag.
- `WhatDid/ActivityRing.swift:28-29,294,325`: `isDragging` and `holding` are reset only in `onEnded`, which doesn't run when the system cancels the gesture (scroll takeover, or the dialog the hold opens). If `holding` stays true, later long-presses are ignored. → Use `@GestureState`, which resets on cancel.
- `WhatDid/WhatDidView.swift:22,49,172,187-190,204,221-233,361`: each `body` decodes `marks` many times (`Stored` decodes on every read), and it rebuilds `spans` about 5 more times. `log` is recomputed in `selectedSpan`, `endingRange` (once per tile through `chipMenu`, about 14 tiles), `today`, `typical`, `dailyAverages`, and `marks.first` runs once per plan row. All history is decoded and grouped every minute and on every 5-min step of a cursor drag, because `cursor` is parent state. `Activity.of` scans `builtIn` and rebuilds `Feeling.all` on each call. → Compute one `WhatDidModel` (spans, planned, moments, totals, typical, days) per `(marks, now-minute)` in an `@Observable` cache, and pass values down. Make `Feeling.all` a stored value that is refreshed on save.
- `WhatDid/WhatDidView.swift:88`: `ActivityAlarms.sync` runs in a fresh unserialized `Task` on every change. If an older Task's `add` lands after a newer Task's remove, a deleted plan keeps its alarm. → Chain the Tasks (same fix as step 04), or cancel the previous one and re-check `marks` after each await.
- `WhatDid/ActivityRing.swift:73-74`: the ring is a single VoiceOver element with only a label. There is no way to move the cursor, so you can't plan or tag at another time without sight. → Add `.accessibilityAdjustableAction` that steps the cursor by 15 min, and a value with the span at the cursor.
- `WhatDid/WhatDidView.swift:351-364,719-726`: `PlanRow`'s alarm `Button` sits inside the row's `Button` label. VoiceOver merges it into the outer button, so the alarm toggle can't be reached. → Make the row an `HStack` with `.onTapGesture` plus `.accessibilityAction`, or add `.accessibilityAction(named: "Toggle alarm")`.
- `WhatDid/WhatDidView.swift` (882 lines): split it, and move the logic out where it can be tested:
  - `ActivityLog+Recording.swift`: `record`, `setTag`, `endingRange` as pure `ActivityLog` functions returning `[ActivityMark]` (the logic behind the P1s above, currently untested).
  - `TagGrid.swift`: `tagGrid`, `tagCell`, `newTagTile`, `chipMenu`, `TagTile`, `StartEndChoice`.
  - `ActivityHistory.swift`: the `activities` section, `spanRow`, `PlanRow`, `SpanRow`, `DayRow`, `TintedIconLabelStyle`.
  - `WhatDidStats.swift`: `today`, `trends`, `stat`, `DayStrip`, `TotalsList`.
  - `MarkEditor.swift`, and `TagEditor.swift` (used by both pages; move it to `Shared/`).
  - What's left is about 200 lines of state, hero and body.
- `Feeling/FeelingView.swift:104-111,113-150,164-190` vs `WhatDidView.swift:193-200,269-289,336-390`: `earliest`/`window`, the 4-column tile grid with a "New" tile, and the day-grouped history with `expandedDays` are copied between the pages. → Extract `TileGrid` and `DayGroupedHistory<Row>`, plus one `timelineStart(spans:now:)`.

## P3
- `WhatDid/ActivityRing.swift:277-279`: `pieces(0, 0)` for a span covering the whole viewed day (possible given the uncapped spans above) draws a zero-length arc, so the full day shows blank. → When `to == from && duration > 0`, return `[(0, 1)]`.
- `WhatDid/ActivityRing.swift:163`: the no-coffee band for tonight also draws on earlier days. → Draw it only when `offset == 0`.
- `WhatDid/ActivityRing.swift:66-72`: focusing a plan on a later day leaves `offset` at 0, and the cursor is outside the window, so it isn't drawn. The centre and the hint show a time with no date. → Add the weekday to the hint when the cursor isn't today.
- `WhatDid/WhatDidView.swift:341,742-743`: DayRow puts a whole span on the day it started, so 23:00–07:00 Sleep is counted on the previous day. The "Today" card uses overlap. → Use `overlap(with:)` per day in DayRow too.
- `WhatDid/WhatDidView.swift:47,84`: `now = max(context.date, .now)` changes on every redraw, so `.task(id: now)` restarts on every cursor step. → Key the task on `context.date`.
- `Feeling/FeelingView.swift:121,153-159` + `FeelingLog.swift:113`: tiles show the state at now, but a tap acts at the cursor time. Ending at a cursor before the feeling's start sets `end = start`, a zero-length span that vanishes without notice. → Derive `active` at the cursor time, and ignore an end that comes before the start.
- `Feeling/FeelingView.swift:47-48`: restyling a custom feeling removes it and appends it again, so it jumps to the end of the grid. → Replace it in place.
- Dead code: `ActivityLog.upSince` (`ActivityLog.swift:237`, used only in tests), `StartEndChoice.isCompact` (`WhatDidView.swift:583`, always false), the `days` value returned by `window()` (`WhatDidView.swift:193-199`, never read), and the unused second tuple field in `planned` (`ActivityLog.swift:145`).
- `WhatDid/ActivityLog.swift:60` + `Feeling/FeelingLog.swift:45`: `Activity.customStyles` and `Feeling.custom` are static caches read once from `AppData.defaults`. After a demo-mode switch or a restore they stay stale until the page appears again. → Read them from the current store, or refresh them in the shared post-restore and demo-switch hook (step 02).
