## P1
- (repo root, no file): there is no `PrivacyInfo.xcprivacy` in either bundle. The app (`Stored`/`@AppStorage`, `AppData.demoDefaults`) and the widget (`Glance.swift:17`, App Group suite) both call `UserDefaults`, which is a required-reason API. App Store Connect rejects uploads that use required-reason APIs without a manifest (ITMS-91053), so `make release` gets as far as the upload and then fails. → add `EveryTime/PrivacyInfo.xcprivacy` (`NSPrivacyAccessedAPICategoryUserDefaults`: `CA92.1`, `1C8F.1`; `NSPrivacyTracking` false; empty collected-data list) and a second copy in `EveryTimeWidget/` (`1C8F.1`). Both bundles pick it up through the existing source globs as a resource. The tracked plist doesn't need excluding.

## P2
- `EveryTimeWidget/EveryTimeWidget.swift:114-118`: `Text(next.target, style: .timer)` counts **up** once the target passes. Entries come once a minute, so a countdown that ends at 12:00:10 shows "0:01, 0:02 … 0:50" counting up until the 12:01 entry. When the Lock Screen delays a refresh, it runs even longer. → use `Text(timerInterval: entry.date...next.target, countsDown: true)` (it stops at 0:00), and add an entry at each `target` within the hour so the next countdown appears right away.
- `EveryTimeWidget/EveryTimeWidget.swift:96,106-121`: the Countdown widget in `.accessoryRectangular` stacks a 2-line caption, a `.largeTitle`/`.title` number and a caption2 date. That is about 16×2 + 41 + 13 + spacing ≈ 92 pt in a slot about 72 pt high, so the Lock Screen clips the name or the date. → branch on `widgetFamily`: for rectangular, use a 1-line name, a `.headline` number and no date line.
- `EveryTimeWidget/EveryTimeWidget.swift:105` vs `Features/Countdown/CountdownReadout.swift:19`: the widget counts calendar days (`dateComponents([.day])`), but the app uses whole 86 400 s blocks. For a countdown across a spring-forward change (e.g. 10:00 Mar 1 → 10:00 Mar 11), the widget shows 10 days while the app shows 9 days. → share one helper (e.g. move `CountdownReadout` into `Glance/` and use it in both).
- `Makefile:39`: `git diff --quiet HEAD --` only warns, and it ignores untracked files. xcodegen globs `EveryTime/`, so an untracked `.swift` file goes into the App Store build without a word. → fail on `git status --porcelain` output (excluding `docs/`) unless `FORCE=1`.
- `scripts/release-ios.sh:10`: `#!/bin/sh` with `set -e` only. There is no `-u`, so a mistyped variable expands to empty. → `#!/usr/bin/env bash` + `set -euo pipefail`. Also check that `Local.xcconfig` doesn't still hold `REPLACE_WITH_YOUR_TEAM_ID` or `com.example`; the current check only tests that the file exists (line 13), so a placeholder fails late at signing.

## P3
- `scripts/release-ios.sh:16`: the build number `date +%Y%m%d%H%M` uses local time. In the repeated hour after the fall-back DST change, a second upload gets a lower number than the first, and two uploads in the same minute get the same number. Either way App Store Connect rejects it only after a full archive. → `date -u +%Y%m%d%H%M`, and check that `BUILD` is numeric when passed.
- `docs/release/privacy-policy.md:23`: says the widget snapshot includes "sleep times". `Glance` (`Glance/Glance.swift:11-12`) holds only cities and countdowns. → drop "sleep times".
- `docs/release/privacy-policy.md:17`: "Nothing from your calendar leaves the device" is not true with iCloud backup on. Picked events are stored with the calendar event title (`CalendarEventPicker.swift:16,19`) under `calendar.since`, which is backed up (`BackupSnapshot.swift:20`). → "…leaves the device, except as part of your own backups (below)."
- `EveryTime/Shared/StoreRegion.swift:7`: `StoreRegion.current` is never read. The `STORE` plumbing (`project.yml:6,13,41`, `Makefile:4`, `release-ios.sh:24`) does nothing. → remove it, or wire it in before a CN listing.
- `project.yml:131-138`: the widget target has no `TARGETED_DEVICE_FAMILY`, so it defaults to iPhone+iPad while the app is iPhone-only (`:86`). → set `"1"` to match.
- `EveryTimeWidget/EveryTimeWidget.swift:28`: the gallery preview falls back to `sample` only when `cities` is empty. That never happens after the first publish (`GlancePublisher.swift:24` defaults the cities), so a user with no countdowns sees "No upcoming countdowns" in the widget gallery. → in preview, use the sample when the needed list (cities or upcoming countdowns) is empty.
- `Makefile:8`: `APP_ID := $(shell sed … Local.xcconfig)` prints a sed error on every `make` call when `Local.xcconfig` is missing. `TEAM_ID` in `.env` duplicates `DEVELOPMENT_TEAM` in `Local.xcconfig` (two sources for one value). → read `TEAM_ID` from `Local.xcconfig` like `APP_ID`, and add `2>/dev/null`.
- `scripts/store-screenshots.sh:13`: lowercase `.heic` isn't matched. `-z 2868 1320` stretches any shot that isn't about 0.46 aspect, with no warning.

## Improvements
- Widgets: add `.widgetURL` (e.g. `everytime://world`, `everytime://countdown/<id>`) so a tap opens the right tab. Add `.accessoryInline`/`.accessoryCircular` for the next countdown. Mark the time text `.widgetAccentable()` for tinted Lock Screen and Home Screen.
- Timeline: the 60 per-minute entries and `.atEnd` give 24 reloads/day per widget, which is within budget. The world clock could use `.after(nextHourStart)` with entries aligned to minute starts (already done). Day-count changes are covered by the per-minute entries. Midnight and DST need nothing extra because times are formatted from absolute dates per zone.
- App Group: one `Data` blob under one key, written by the app only, so the widget can't see a half-written snapshot. No race found. Consider `Glance.shared` failing loudly (assert) instead of falling back to `.standard`, because a missing App Group entitlement then shows up as an always-empty widget.
- Release: run `xcodebuild test` (or `make build`) before `archive`. Print the archive path on failure. Optionally `xcrun altool --validate-app` before upload.
- Boards exclusion is clean: nothing outside `Features/Boards/` references Board types, tests are excluded by `Board*.swift`, and no Reminders usage string or entitlement ships. The leftover `"boards."` in `BackupSnapshot.keyPrefixes` is harmless. Keep it so old backups round-trip.
- Entitlements match the code: time-sensitive is used (`NapAlarm.swift:176,196`), HealthKit is read-only, and the iCloud container and App Group come from `APP_BUNDLE_ID`. Network use is only the Wikipedia fetch (`OnThisDay.swift:46`), which the policy covers. `ITSAppUsesNonExemptEncryption: false` is correct (HTTPS only).
